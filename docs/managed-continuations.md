# Explicit managed background callbacks

Candidate-only v1 integration; not generic timer interception and not real-provider acceptance.

The manager registers `Symbol.for("pi.managed-continuation.registry.v1")` endpoints in a WeakMap keyed by the exact child `sessionManager`, before extension binding and before exposing the session. Callback producers synchronously acquire a lease before launching work and admit a stable delivery ID with the actual custom message and options. Admission ACK is separate from execution completion. Repeated delivery IDs share completion without another model execution. Foreign/released leases and closed endpoints reject; never fall back to the root session.

Callbacks accept triggering `steer`/`followUp` only; `nextTurn` is rejected because its SDK send resolves before execution. Session idle is checked before send. Callbacks serialize per child, reserve the background queue before executing, and use the existing runner's fresh abort, capture, tool scope, loop reset, limits, structured recovery and provider-error inspection. Nested ownership remains excluded from top-level pools. Effective callback maxTurns/hardLimit are captured at original invocation, not reread from mutable configuration. Explicit resumes retain their existing prompt API.

Initial completion is published normally and frees its pool slot even with pending leases. The last published result stays on the record while a callback waits/runs. Each publication increments `resultRevision`; consumption and notification snapshots are revision scoped. Autonomous completion bypasses initial batch join state. Lifecycle events, persisted records, XML notifications and result text carry the revision. RPC `consume` accepts an optional positive `resultRevision` (omission retains terminal-current behavior).

The queue-reservation promise spans publication, and active execution ownership survives public stop until settlement. Leases and admitted execution retain the child/worktree. Releasing the last lease allows deferred cleanup exactly once. GC skips only explicitly retained records, not the whole fleet. Stop/dispose close the endpoint before abort; tombstones remain in the weak registry but detach manager/session closures. Stable completion receipts carry only outcomes, not full session transcripts. Cleanup closes the endpoint before removing its worktree so no new callback can enter that directory. If deferred cleanup adds saved-branch instructions, it publishes a new autonomous result revision through the normal notification/persistence path; it does not silently alter a published revision. The output file remains the model transcript, not a worktree-artifact log: use the revisioned result/event/persisted record for branch instructions.

Unknown autonomous sources, generic timers and uncontracted direct session sends are unresolved separately. Real-provider control/treatment and installed-system acceptance remain the parent coordinator's gate.
